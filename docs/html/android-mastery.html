02 / ViewModel

Surviving Config Changes

StateFlowSavedStateHandle
Kotlin · ViewModel
@HiltViewModel
class MyViewModel @Inject constructor(
    private val repository: MyRepository,
    private val savedStateHandle: SavedStateHandle // survives process death
) : ViewModel() {

    private val _uiState = MutableStateFlow<UiState>(UiState.Loading)
    val uiState: StateFlow<UiState> = _uiState.asStateFlow()

    // SavedStateHandle — survives process death (small data only)
    val searchQuery = savedStateHandle.getStateFlow("query", "")

    fun onAction(action: Action) {
        viewModelScope.launch { // auto-cancelled on onCleared()
            when (action) {
                is Action.Refresh -> loadData()
                is Action.Search -> savedStateHandle["query"] = action.query
            }
        }
    }
}
Tip

Use SavedStateHandle for: search queries, scroll position, selected tab, form input. Do NOT use for: network responses, large data — use Repository/cache instead.

Kotlin · State Hoisting
// State hoisting: stateful wrapper → stateless component
@Composable
fun CounterScreen() {
    var count by rememberSaveable { mutableStateOf(0) }
    // State flows DOWN, events flow UP
    StatelessCounter(count = count, onIncrement = { count++ })
}

@Composable
fun StatelessCounter(count: Int, onIncrement: () -> Unit) {
    Button(onClick = onIncrement) { Text("Count: $count") }
}

// Collecting ViewModel state — THE correct way
val uiState by viewModel.uiState.collectAsStateWithLifecycle()
Common Mistake

Using collectAsState() instead of collectAsStateWithLifecycle(). The former keeps collecting when the app is backgrounded — wasting resources and risking crashes from invisible UI updates.

Tip

LaunchedEffect vs rememberCoroutineScope: LaunchedEffect for composition lifecycle (auto-run on enter). rememberCoroutineScope for user events (button clicks, gestures). Never use LaunchedEffect for click handlers.

05 / Performance

Lists & Stability

LazyColumn@StableModifier

LazyColumn performance rules:

  1. Always provide key — enables correct diffing and state preservation across reorder
  2. Use contentType — Compose reuses compositions between same-type items (huge win for mixed lists)
  3. Keep items @Stable — use immutable data classes, @Immutable annotation
  4. Modifier order matters! — .clickable{}.padding(16.dp) ≠ .padding(16.dp).clickable{}
  5. Use derivedStateOf for scroll-dependent state (show/hide FAB)
Warning

Never nest LazyColumn inside LazyColumn. Use nested items() calls or sections within a single LazyColumn instead.

06 / Architecture

MVVM + Clean

MVVMRepositoryUDF
Kotlin · Architecture Flow
// Clean Architecture layers:
// Presentation (UI + ViewModel) → Domain (UseCases) → Data (Repository + API/DB)
//
// UDF: state flows DOWN, events flow UP
// UI ──(Action)──→ ViewModel ──→ UseCase ──→ Repository
// UI ←──(State)─── ViewModel ←── UseCase ←── Repository

// Sealed interface for UI State
sealed interface UiState<out T> {
    data object Loading : UiState<Nothing>
    data class Success<T>(val data: T) : UiState<T>
    data class Error(val msg: String) : UiState<Nothing>
}

// Use Case with operator invoke
class GetArticlesUseCase @Inject constructor(
    private val repo: ArticleRepository
) {
    operator fun invoke(): Flow<List<Article>> = repo.observeArticles()
}
Note

Use Cases are OPTIONAL. Google's official guidance says skip them if they're just pass-through. Add them when: business logic exists, multiple repos need coordination, or logic is shared across ViewModels.

Kotlin · Safe API Call
sealed class NetworkResult<out T> {
    data class Success<T>(val data: T) : NetworkResult<T>()
    data class Error(val code: Int, val msg: String) : NetworkResult<Nothing>()
    data class Exception(val e: Throwable) : NetworkResult<Nothing>()
}

suspend fun <T> safeApiCall(call: suspend () -> Response<T>): NetworkResult<T> {
    return try {
        val response = call()
        if (response.isSuccessful) NetworkResult.Success(response.body()!!)
        else NetworkResult.Error(response.code(), response.message())
    } catch (e: IOException) { NetworkResult.Exception(e) }
}

Kotlin · Lifecycle-Aware Collection
// In Compose: collectAsStateWithLifecycle handles it
val state by viewModel.uiState.collectAsStateWithLifecycle()

lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.uiState.collect { state -> updateUI(state) }

12 / Testing

Unit & UI Tests

JUnit5TurbineFakes
Kotlin · ViewModel Test
@OptIn(ExperimentalCoroutinesApi::class)
class MyViewModelTest {
    private val testDispatcher = UnconfinedTestDispatcher()

    @BeforeEach fun setup() { Dispatchers.setMain(testDispatcher) }
    @AfterEach fun tearDown() { Dispatchers.resetMain() }

    @Test
    fun `refresh shows success`() = runTest {
        val vm = MyViewModel(FakeRepository())
        vm.uiState.test { // Turbine
            assertThat(awaitItem()).isInstanceOf(UiState.Loading::class)
            vm.onAction(Action.Refresh)
            assertThat(awaitItem()).isInstanceOf(UiState.Success::class)
        }
    }
}
Definition

Fake vs Mock: Fake = real implementation with simplified logic (reusable, catches contract bugs). Mock = framework stub (per-test setup, only verifies what you specify). Prefer Fakes for repositories, Mocks for third-party dependencies.

13 / Interview

Q&A with Answers

Must-KnowSenior Level
#QuestionAnswer
⭐1What happens on rotation?Activity destroyed + recreated. ViewModel survives (held by ViewModelStore). SavedStateHandle survives. Composables recompose.
⭐2remember vs rememberSaveable?remember: survives recomposition. rememberSaveable: + config changes (Bundle). Neither survives process death.
⭐3collectAsStateWithLifecycle?Stops collecting when lifecycle < STARTED. Prevents wasted work and crashes while backgrounded. Always use instead of collectAsState.
⭐4MVVM vs MVI?MVVM: multiple state flows, simpler. MVI: single state object, better for complex state. Default to MVVM; use MVI when state interactions are complex.
⭐5@Provides vs @Binds?@Provides for types you don't own (Retrofit). @Binds for interface→impl (more efficient, no factory class). @Provides needs object module, @Binds needs abstract class.
⭐6LaunchedEffect vs rememberCoroutineScope?LaunchedEffect: auto-runs on composition/key change (lifecycle-driven). rememberCoroutineScope: for user events (clicks). Never use LaunchedEffect for click handlers.
7Room Flow queries?Auto-emit when table changes. No manual refresh. Suspend for writes, Flow for reads. @Transaction for atomic multi-ops.
8viewModelScope vs lifecycleScope?viewModelScope: ViewModel lifetime, auto-cancel on onCleared(). lifecycleScope: Activity/Fragment lifetime. viewModelScope for business logic, lifecycleScope for UI.
9WorkManager vs Service?WorkManager: guaranteed execution, constraints, survives death. Service: long-running foreground work (music, GPS). WorkManager for most background tasks.
⭐10Compose stability?@Stable/@Immutable: tell Compose to skip recomposition if unchanged. Use immutable data classes. Provide key in LazyColumn. Modifier order matters.
11ANR causes?Main thread blocked >5s. Causes: I/O on main, heavy computation, deadlock. Fix: withContext(IO), WorkManager, async.
12Repository pattern?Single source of truth. Abstracts data sources (API/DB). UI observes local DB via Flow. API syncs to DB. Testable with fakes.
13Process death?ViewModel is GONE. SavedStateHandle survives. onSaveInstanceState survives. Save small UI state (IDs, positions), not data.
⭐14StateFlow vs LiveData?StateFlow: Kotlin-native, richer operators, testable with Turbine, needs lifecycle handling. LiveData: Android, auto lifecycle-aware, limited operators. Modern: StateFlow + collectAsStateWithLifecycle.
15popUpTo inclusive?popUpTo("route"): pops until reaching route. inclusive=true: also pops the route. Used for login→home (clear login from stack).
16Application vs Network interceptor?Application: runs once, sees original request (auth headers). Network: runs per request including redirects (caching). Token→Application, cache→Network.
17DataStore vs SharedPrefs?DataStore: async (Flow+suspend), type-safe, transactional, no ANR. SharedPrefs: sync, ANR risk, not type-safe. Always prefer DataStore.
18Fakes vs Mocks?Fakes: real implementations, reusable, catch contract bugs. Mocks: framework stubs, per-test. Prefer fakes for repositories.
19derivedStateOf when?When computed value depends on state but is read more often than source changes. Example: isScrolledPast from scrollPosition.
⭐20Design a feature from scratch?1) Define UiState sealed interface, 2) ViewModel with StateFlow, 3) Actions sealed interface, 4) Repository interface, 5) Hilt module, 6) Testing strategy.
