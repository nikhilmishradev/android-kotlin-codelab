Variables & Type System

Warning

val list = mutableListOf(1, 2, 3) — the reference is read-only but the list contents can change. val ≠ immutable!

lateinit vs lazy

Featurelateinitby lazy
Keywordlateinit varval by lazy { }

Kotlin
// val vs var
val immutable = "can't reassign"
var mutable = "can reassign"
mutable = "changed!"

// lateinit — for non-null vars initialized later (DI, Android)
lateinit var name: String
name = "Nikhil"

// lazy — computed on first access, then cached
val expensive: String by lazy {
    println("Computing...")
    "result"
}
println(expensive) // prints "Computing..." then "result"
println(expensive) // prints "result" only (cached)

Type Hierarchy

Any is the root of all non-nullable types (like Java's Object). Unit is Kotlin's void — it's an actual object. Nothing is the bottom type — subtype of everything. Functions returning Nothing never return (always throw). This is why val x: String = nullableStr ?: throw Exception() compiles — throw returns Nothing, which is a subtype of String.

02 / Safety

Null Safety

?.?:!!
OperatorNameBehaviorWhen to Use
?.Safe callReturns null if receiver is nullDefault choice — always safe
?:ElvisProvides fallback if left side is nullDefault values, early returns
!!Non-null assertionThrows NPE if nullAlmost never. Only when you're 100% certain
?.let { }Safe letExecutes block only if non-nullTransform + null check in one step
as?Safe castReturns null if cast failsType checking without crash
Kotlin · Null Safety
val name: String? = null

// Safe call
val len = name?.length          // null (no crash)

// Elvis — fallback
val len2 = name?.length ?: 0    // 0

// Elvis with throw (common in Android)
val id = intent.getStringExtra("id")
    ?: throw IllegalArgumentException("id required")

// Safe let — execute block only if non-null
name?.let { println("Name is $it") } // skipped

// Smart cast after null check
if (name != null) {
    println(name.length) // compiler knows name is String here
}
Common Mistake

Using !! everywhere "because I know it's not null." This defeats Kotlin's null safety. Use ?: with a default or requireNotNull() with a message instead.

03 / Control Flow

Expressions & Patterns

whenif expressionranges

In Kotlin, if and when are expressions — they return values. No ternary operator needed.

Kotlin
// if is an expression — returns a value
val max = if (a > b) a else b

// when — exhaustive with sealed classes
val result = when (state) {
    is State.Loading -> "Loading..."
    is State.Success -> "Data: ${state.data}"
    is State.Error   -> "Error: ${state.msg}"
    // No else needed — compiler enforces all cases!
}

// when with ranges, type checks, multiple values
fun classify(x: Any): String = when (x) {
    in 1..10       -> "small number"
    is String      -> "string of length ${x.length}" // smart cast
    "hello", "hi"  -> "greeting"
    else           -> "unknown"
}
Warning

when as statement (no assignment) is NOT exhaustive! Missing branches compile silently. Always use when as an expression (val x = when...) with sealed classes to get compile-time safety.

04 / OOP

Classes & Objects

data classsealedobjectvalue class

Data Classes — What's Generated?

Compiler generates from primary constructor properties only: equals(), hashCode(), toString(), copy(), componentN().

Common Mistake

Body properties are EXCLUDED from equals/hashCode/toString! data class User(val name: String) { var age = 0 } — two Users with different ages are still "equal" because age is in the body, not the constructor.

Common Mistake

copy() is SHALLOW. val copy = original.copy() shares the same list references. Mutating copy.tags.add("x") also modifies the original! Fix: original.copy(tags = original.tags.toMutableList())

Sealed Classes vs Enums

FeatureSealed Class/InterfaceEnum Class
Subclass stateEach subclass can hold different dataAll entries share same structure
Instance countMultiple instances per subclassFixed singleton per entry
Exhaustive whenYes (as expression)Yes
InheritanceSubclasses can be data/object/regularAll are the same enum type
Use caseUI state, Result types, navigationFixed sets (Direction, Status)
Kotlin · Sealed + Object
// Sealed — perfect for UI state
sealed interface UiState<out T> {
    data object Loading : UiState<Nothing>
    data class Success<T>(val data: T) : UiState<T>
    data class Error(val msg: String) : UiState<Nothing>
}

// Object = singleton
object Logger { fun log(msg: String) = println(msg) }

// Companion object = "static" in Kotlin
class User(val name: String) {
    companion object {
        const val MAX_NAME = 50
        fun create(name: String) = User(name)
    }
}
val user = User.create("Alice") // called like static

// Value class — type safety, zero runtime cost
@JvmInline value class Email(val value: String)
@JvmInline value class UserId(val value: Int)
// Can't accidentally pass UserId where Email is expected!

Init Block Order

Properties and init blocks execute in textual order — not "all properties first" or "all inits first." This surprises many developers.

Tip

Never access open/overridable properties in init blocks. When a derived class overrides a property, the base class init runs first — before the derived property is initialized. The compiler warns about this.

val len: Int? = name?.let { it.length }

// apply — configure object (returns the object)
val user = User().apply {
    name = "Alice"
    email = "alice@test.com"
}

// also — side effects (returns the object)
val list = mutableListOf(1, 2, 3)
    .also { println("Before: $it") }
    .also { it.add(4) }

Extension Functions

Note

Extensions are resolved statically at compile time. They can't access private members. If a member function has the same signature, member always wins. Extensions don't support polymorphism — animal.ext() calls Animal.ext, not Dog.ext, regardless of runtime type.

06 / Collections

Functional Operations

SequencesTransformationsAggregation

Key Operations

Kotlin · Collections
val nums = listOf(1, 2, 3, 4, 5)

// map — transform each element
nums.map { it * 2 }           // [2, 4, 6, 8, 10]

// flatMap — map + flatten
listOf("Hello World", "Kotlin")
    .flatMap { it.split(" ") } // [Hello, World, Kotlin]

// filter, partition
val (evens, odds) = nums.partition { it % 2 == 0 }

// groupBy vs associateBy
users.groupBy { it.dept }     // Map<String, List<User>> — ALL values
users.associateBy { it.dept } // Map<String, User> — LAST wins! Duplicates LOST

// fold vs reduce
nums.fold(10) { acc, n -> acc + n } // 25 (10 + 1+2+3+4+5)
nums.reduce { acc, n -> acc + n }   // 15 (starts from first element)
Warning

reduce crashes on empty list! Use fold when the list might be empty. Also: emptyList<Int>().all { it > 100 } returns true (vacuous truth) — a common interview trap.

Sequence vs List

FeatureList (Eager)Sequence (Lazy)
EvaluationEach operation processes ALL elementsElement-by-element through all operations
Intermediate resultsCreates new list per stepNo intermediate collections
Short-circuitNo — processes everythingYes — first() stops early
When to useSmall collections, simple chainsLarge collections, chained operations, first/take

07 / Generics

Variance & Reified

in / outreifiedstar projection
VarianceKeywordDirectionExampleMnemonic
Covariantout TOnly returned (produced)List<out E>, Flow<out T>Producer = Out
Contravariantin TOnly accepted (consumed)Comparable<in T>, Comparator<in T>Consumer = In
Invariant(default)Both read and writeMutableList<T>No keyword
Kotlin · Variance
// COVARIANT — Producer<Dog> IS-A Producer<Animal>
class Producer<out T>(val value: T) {
    fun produce(): T = value
    // fun consume(item: T) {} // ERROR! Can't use T in 'in' position
}
val dogs: List<Dog> = listOf(Dog())
val animals: List<Animal> = dogs // OK! List is covariant (out)

// REIFIED — access generic type at runtime (requires inline)
inline fun <reified T> isType(value: Any): Boolean = value is T
isType<String>("hello") // true — works because reified!
Definition

Type Erasure: JVM erases generic types at runtime. List<String> and List<Int> are both just List. Reified + inline is Kotlin's workaround — the compiler substitutes the actual type at each call site.

08 / Delegation

Composition Over Inheritance

by lazyby observableclass delegation
Kotlin · Delegation
// Class delegation — avoids inheritance
class PrefixLogger(printer: Printer, val prefix: String)
    : Printer by printer {
    override fun print(msg: String) = println("$prefix $msg")
}

// lazy — computed on first access
val expensive by lazy { computeExpensiveValue() }

// observable — callback on every change
var name by Delegates.observable("initial") { _, old, new ->
    println("$old → $new")
}

// vetoable — can REJECT the change
var age by Delegates.vetoable(0) { _, _, new -> new >= 0 }
Tip

Kotlin classes are final by default. This pushes you toward composition/delegation by design. Prefer delegation over inheritance — it avoids the fragile base class problem and allows composing multiple behaviors.

09 / Coroutines

Structured Concurrency

BuilderReturnsUse CaseResult

Common Mistake

withContext is SEQUENTIAL! Two withContext(IO) calls = 200ms, not 100ms. Use async { } + await() for parallel execution.

coroutineScope vs supervisorScope

FeaturecoroutineScopesupervisorScope
Child failsALL siblings cancelledOnly that child dies
ExceptionPropagates upHandled per-child
Use caseRelated tasks (all must succeed)Independent tasks (viewModelScope)
Kotlin · Dispatchers
// Dispatchers
Dispatchers.Main      // UI thread (Android)
Dispatchers.IO        // Network, disk I/O (up to 64 threads)
Dispatchers.Default   // CPU-intensive (cores count)
Dispatchers.Unconfined // Starts in caller, resumes anywhere

// Parallel with async
coroutineScope {
    val user = async { api.getUser() }
    val posts = async { api.getPosts() }
    // Both run concurrently! Total = max(userTime, postsTime)
    showDashboard(user.await(), posts.await())
}

// Cancellation is COOPERATIVE
val job = launch {
    while (isActive) { // must check!
        doWork()
        delay(100) // delay is a cancellation point
    }
}
job.cancel() // only works because we check isActive/delay

10 / Flow

Reactive Streams

StateFlowSharedFlowCold vs Hot
FeatureFlow (cold)StateFlow (hot)SharedFlow (hot)
StartsOn collect()ImmediatelyImmediately
Initial valueNoYes (always has value)No
ReplayRestarts per collectorLatest value (replay=1)Configurable
DeduplicationNoYes (equals())No
Use caseRoom queries, one-shotUI state in ViewModelEvents (nav, snackbar)
Warning

StateFlow deduplicates! Setting the same value won't emit. If you mutate a data class and re-emit the same reference, StateFlow won't notify collectors because equals() returns true. Always use .copy() to create new objects.

Warning

collectLatest CANCELS previous processing! If your collector does slow work (DB save), use collect not collectLatest. collectLatest is for search-as-you-type where you want to discard stale results.

11 / DSL

Domain Specific Languages

Lambda with Receiver@DslMarker
Kotlin · DSL Pattern
// Lambda with receiver: T.() -> Unit
// Inside the lambda, 'this' is the receiver
fun server(block: ServerConfig.() -> Unit): ServerConfig =
    ServerConfig().apply(block)

val config = server {
    host = "localhost"  // 'this' is ServerConfig
    port = 8080
    database {          // nested lambda with receiver
        url = "jdbc:..."
    }
}

// This is EXACTLY how Gradle KTS, Compose, and Ktor work:
// dependencies { implementation(...) } ← lambda with receiver
// Column { Text("...") }               ← @Composable lambda
Note

@DslMarker prevents scope leaking — inner lambdas can only access their own receiver, not outer receivers. Without it, you could accidentally call body { body { } } accessing the outer html receiver.

12 / Puzzles

Predict the Output

InterviewTrickyMust-Know

These are the exact puzzles asked in Android interviews. Predict the output before reading the answer.

Puzzle 1: async ordering

Kotlin · Puzzle
val d1 = async { delay(100); println("First"); 10 }
val d2 = async { delay(50); println("Second"); 20 }
println(d1.await())
println(d2.await())

Answer: Second, First, 10, 20. Both start immediately. d2 finishes first (50ms) but d1.await() suspends until d1 completes.

Puzzle 2: data class body property

Kotlin · Puzzle
data class Person(val name: String) { var age: Int = 0 }
val p1 = Person("Alice").apply { age = 25 }
val p2 = Person("Alice").apply { age = 99 }
println(p1 == p2) // ?

Answer: true. Body properties (age) are excluded from equals(). Only constructor params (name) participate.

Puzzle 3: reduce on empty

Kotlin · Puzzle
emptyList<Int>().reduce { acc, n -> acc + n } // ?
emptyList<Int>().all { it > 1000 }            // ?

Answer: reduce throws UnsupportedOperationException. all() returns true (vacuous truth). Use fold() for safe aggregation.

Puzzle 4: launch order

Kotlin · Puzzle
launch { println("A") }
launch { println("B") }
println("C")

Answer: C, A, B. launch{} schedules but doesn't execute immediately. Current coroutine continues first.

Puzzle 5: StateFlow dedup

Kotlin · Puzzle
val sf = MutableStateFlow(1)
sf.value = 1  // same value
sf.value = 2
sf.value = 2  // same again
sf.value = 3
// How many emissions? What values?

Answer: 3 emissions: 1 (initial), 2, 3. Duplicate values are skipped by equals().

13 / Interview

Q&A with Answers

Must-KnowSenior Level
#QuestionAnswer
⭐1val vs var?val = read-only reference (NOT immutable — contents can change). var = reassignable. const val = compile-time constant (primitives/String only, top-level or companion).
⭐2== vs ===?== is structural equality (calls equals()). === is referential equality (same object in memory). Kotlin's == is null-safe.
⭐3What does data class generate?equals(), hashCode(), toString(), copy(), componentN() — from PRIMARY CONSTRUCTOR properties only. Body properties are excluded.
⭐4Sealed class vs enum?Sealed: subclasses can hold different state, can be data/object/regular. Enum: fixed singleton instances, same structure. Use sealed for UI state, enum for fixed sets.
⭐5launch vs async?launch = fire-and-forget (Job, no result). async = returns Deferred<T>, call .await() for result. Use async for parallel work.
6Scope functions — when to use which?let(it→result): null check. apply(this→obj): configure. also(it→obj): side effects. run(this→result): config+compute. with(this→result): group calls.
7What is reified?Preserves generic type at runtime. Requires inline. Enables is T checks and T::class. Without it, type is erased by JVM.
⭐8Coroutine vs Thread?Coroutine: lightweight (many per thread), suspendable, structured. Thread: OS-level, expensive (1MB stack), blocking. 10K coroutines = fine. 10K threads = crash.
⭐9StateFlow vs SharedFlow?StateFlow: always has value, deduplicates (equals), replay=1. Use for UI state. SharedFlow: no initial value, configurable replay. Use for events (navigation, snackbar).
⭐10Flow vs LiveData?Flow: Kotlin-native, richer operators, cold, not lifecycle-aware by default. LiveData: Android, lifecycle-aware, limited operators. Modern: Flow + collectAsStateWithLifecycle().
11Structured concurrency?Coroutines form parent-child trees. Parent waits for children. If parent cancels → children cancel. If child fails → parent knows. No leaked/orphaned coroutines.
12Variance: in vs out?out = producer (covariant): Producer<Dog> IS-A Producer<Animal>. in = consumer (contravariant): Consumer<Animal> IS-A Consumer<Dog>. POCI mnemonic.
13Extension function limits?Resolved statically (compile time). Can't access private members. Member function always wins over extension. No polymorphism.
14lateinit vs lazy?lateinit: var, non-null, manual init, not thread-safe. lazy: val, auto-init on first access, thread-safe (SYNCHRONIZED).
15Nothing type?Bottom type — subtype of everything. For functions that never return (throw). Enables val x = nullable ?: fail("msg") to compile because Nothing is subtype of any type.
⭐16coroutineScope vs supervisorScope?coroutineScope: one child fails → all siblings cancelled. supervisorScope: child failure is isolated, siblings continue. viewModelScope uses SupervisorJob.
17withContext vs launch?withContext: sequential (suspends, returns result). launch: concurrent (doesn't return result). Use withContext for dispatcher switching, launch for fire-and-forget.
18What is inline good for?Copies function body at call site. Avoids lambda object allocation for higher-order functions. Required for reified type parameters.
19Object vs companion object?Object: standalone singleton. Companion: belongs to a class, accessed via class name (like static). Companion can implement interfaces.
20Nested vs inner class?Nested (default): no reference to outer, no memory leak risk. Inner: holds outer reference, can access outer members, memory leak risk. Prefer nested.
⭐21copy() shallow trap?copy() is shallow — shared mutable collections are the SAME reference. Modifying the copy's list modifies the original. Fix: copy(list = list.toMutableList())
22Cancellation cooperative?Coroutines must check for cancellation (isActive, ensureActive, yield). delay() is a cancellation point. Thread.sleep() is NOT — ignores cancel.
23collectLatest behavior?Cancels previous collection when new value arrives. Only the latest value completes processing. Use for search-as-you-type. DON'T use for DB saves.
24Value class benefit?Type safety with zero runtime cost. At runtime, Email("x") is just the String "x". At compile time, Email and Username are distinct types — prevents mixing.
⭐25equals/hashCode contract?If a == b, then a.hashCode() == b.hashCode(). Breaking this (override equals but not hashCode) breaks HashMap — lookup returns null even for "equal" keys.
