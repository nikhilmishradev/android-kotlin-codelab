02 / Kotlin Foundations

What Seniors Must Know

Days 1–3 Kotlin Fundamentals

At 8 years, you use Kotlin daily. But can you explain the difference between == and === on the spot? Can you list what data class generates and what it doesn't? These are the gaps interviews expose.

Definition

Priority System: 🔴 MUST = always asked, 🟡 SHOULD = frequently asked, 🟢 NICE = occasionally asked.

TopicPriorityWhat Interviewers Actually Ask
Null Safety🔴 MUSTDifference between ?., ?:, !!. When to use each. Platform types.
Data Classes🔴 MUSTWhat's generated? What happens with body properties? Copy() shallow copy trap.
Sealed Classes🔴 MUSTvs Enum. When to use. Exhaustive when (expression vs statement!).
Scope Functions🔴 MUSTlet/run/with/apply/also — context object (it vs this) and return value.
Collections🟡 SHOULDmap vs flatMap. Sequence vs List. reduce vs fold (empty list crash!).
val vs var🟡 SHOULDRead-only vs mutable. const val. lateinit vs lazy.
Type System🟡 SHOULDAny, Unit, Nothing. Smart cast. Type aliases. Value classes.
Equality🟡 SHOULD== (structural) vs === (referential). equals/hashCode contract.
Extensions🟢 NICEResolved statically. Can't access private members. Member always wins.
Tip

Use the codelab project! Run KotlinBasics.kt, KotlinOOP.kt, KotlinFunctions.kt, and KotlinCollections.kt — each has a main() function with output you can study. Then run OOPInterviewPuzzles.kt and CollectionsInterviewPuzzles.kt to test yourself.

Day 1: Variables, Types, Null Safety

Review val vs var, const val, lateinit vs lazy. Practice null safety operators until you can explain each one's use case in 10 seconds.

Day 2: OOP — Classes, Sealed, Data, Enum

Focus on data class traps (body properties excluded, copy() is shallow), sealed class exhaustiveness (when expression vs statement), and init block execution order (textual, not grouped).

Day 3: Functions, Scope Functions, Collections

Memorize the scope functions table. Practice collection chains. Know when reduce crashes (empty list) and why all {} on empty returns true (vacuous truth).

03 / Kotlin Advanced

The Differentiators

Days 4–6 Coroutines Flow

This is where Senior separates from Mid-level. Coroutines and Flow are not optional — they're the foundation of modern Android concurrency. Generics variance (in/out) and delegation are frequently asked at Senior level.

TopicPrioritySenior-Level Focus
Coroutines Basics🔴 MUSTlaunch vs async vs withContext. Dispatchers. Structured concurrency.
Exception Handling🔴 MUSTcoroutineScope vs supervisorScope. CEH only with launch. try-catch placement.
Flow🔴 MUSTCold vs hot. StateFlow vs SharedFlow (deduplication!). collectLatest cancellation.
Cancellation🟡 SHOULDCooperative. isActive/ensureActive. NonCancellable for cleanup. Thread.sleep trap.
Generics Variance🟡 SHOULDout = producer (covariant), in = consumer (contravariant). POCI mnemonic.
Delegation🟡 SHOULDby lazy, observable/vetoable, class delegation. Composition over inheritance.
Channels🟢 NICEFan-out (each value consumed once). Channel types.

Key Puzzle: Predict the Output

Kotlin · Interview Puzzle 
fun main() = runBlocking {
    val d1 = async { delay(100); println("First"); 10 }
    val d2 = async { delay(50); println("Second"); 20 }
    println(d1.await())
    println(d2.await())
}
Note

Answer: Second, First, 10, 20. Both async blocks start immediately. d2 finishes first (50ms < 100ms) but d1.await() is called first — it suspends until d1 completes. By then d2 is already done. await() doesn't start the coroutine — it just waits for the result.

Common Mistake

withContext is SEQUENTIAL, not parallel. Two withContext(IO) calls take 200ms total, not 100ms. Use async + await for parallel execution. This is the most common coroutine interview trap.

04 / Android Core

The Foundation

Days 7–9 Lifecycle ViewModel

Lifecycle questions are always asked. Even at Senior level. The difference is they ask scenario-based questions, not "list the callbacks."

Warning

Trick questions interviewers love:

• "What happens when the user rotates the device?" → Activity destroyed + recreated, ViewModel survives, SavedStateHandle survives, onSaveInstanceState called.

• "What about process death?" → ViewModel is GONE. Only SavedStateHandle and onSaveInstanceState survive.

• "Can a ViewModel reference a Context?" → NO. It outlives the Activity → memory leak. Use Application context via AndroidViewModel only if absolutely needed.

ScenarioActivityViewModelSavedStateHandle
RotationDestroyed + recreated✅ Survives✅ Survives
Back pressDestroyed (finish)❌ Cleared❌ Gone
Process deathDestroyed❌ Gone✅ Survives
Home + returnStopped → Started✅ Survives✅ Survives

What to Study

  • 🔴 Activity & Fragment lifecycle callbacks and their order
  • 🔴 ViewModel: how it survives config changes, viewModelScope auto-cancellation
  • 🔴 SavedStateHandle: what to save (UI state, IDs) vs what NOT to save (data)
  • 🟡 Navigation Component: arguments, back stack, popUpTo with inclusive
  • 🟡 Room + DataStore: Flow-based queries, migrations, DataStore vs SharedPrefs

05 / Jetpack Compose

The Modern Must-Have

Days 10–12 Compose State

Compose is no longer optional for Senior roles. Most companies have adopted it or are migrating. Focus on state management and performance — that's what separates knowing Compose from mastering it.

Focus AreaPriorityKey Concepts
State Management🔴 MUSTremember, rememberSaveable, mutableStateOf, state hoisting, derivedStateOf
Side Effects🔴 MUSTLaunchedEffect, DisposableEffect, SideEffect, rememberCoroutineScope
Performance🔴 MUST@Stable, @Immutable, key in LazyColumn, Modifier order matters
Flow Collection🔴 MUSTcollectAsStateWithLifecycle (NOT collectAsState)
Navigation🟡 SHOULDNavHost, composable destinations, argument passing
Animations🟢 NICEAnimatedVisibility, animateAsState, animateContentSize
Tip

The #1 Compose interview question: "What's the difference between remember and rememberSaveable?" → remember survives recomposition only. rememberSaveable survives recomposition AND configuration changes (uses Bundle). Neither survives process death — use SavedStateHandle in ViewModel for that.

Common Mistake

Using collectAsState() instead of collectAsStateWithLifecycle(). The former keeps collecting even when the app is backgrounded — wasting resources and potentially crashing from UI updates while invisible.

06 / Architecture

Think Like a Senior

Days 13–14 MVVM Clean Architecture

Seniors don't just implement features — they design systems. You need to articulate why you choose MVVM over MVI, when Use Cases add value vs when they're overhead, and how UDF keeps state predictable.

Kotlin · Architecture Pattern 
// UDF: State flows DOWN, events flow UP
//
// UI ──(Action)──→ ViewModel ──→ UseCase ──→ Repository
// UI ←──(State)─── ViewModel ←── UseCase ←── Repository
//
// One-time events: SharedFlow (replay=0)
// UI state: StateFlow (always has value)

sealed interface UiState<out T> {
    data object Loading : UiState<Nothing>
    data class Success<T>(val data: T) : UiState<T>
    data class Error(val msg: String) : UiState<Nothing>
}
Note

Whiteboard exercise: "Design a feature from scratch." Start with: UI State sealed interface → ViewModel with StateFlow → Actions sealed interface → Repository → API/DB. Draw the data flow arrows. Mention testing strategy (fake repository). This is what interviewers want to see.

MVVM vs MVI — When Asked

AspectMVVMMVI
StateMultiple StateFlows possibleSingle state object
ComplexitySimpler for most screensBetter for complex interactions
DebuggingMultiple state sourcesSingle source of truth, time-travel
RecommendationDefault choiceWhen state interactions are complex

07 / DI & Networking

The Practical Layer

Days 15–16 Hilt Retrofit

At Senior level, they won't ask "what is DI?" They'll ask "explain the difference between @Provides and @Binds" or "how do you handle token refresh transparently?"

Concept@Provides@Binds
Used forTypes you DON'T own (Retrofit, OkHttp)Types you DO own (interface → impl)
Module typeobject (concrete)abstract class (abstract)
PerformanceGenerates factory classMore efficient (no factory)
When to useThird-party, complex creationSimple interface binding
Tip

OkHttp interceptor question: Application interceptors run ONCE per request (add auth headers). Network interceptors run for EVERY request including redirects (caching, compression). Auth token goes in application interceptor. Token refresh goes in Authenticator.

09 / System Design

Android at Scale

Days 17–18 Architecture Scale

This is THE Senior differentiator. Companies want to know you can think beyond a single screen. Prepare to discuss these topics at a whiteboard.

Warning

If you skip this section, you will plateau at Mid-Senior offers. System design is what gets you the Senior title and salary.

Topics to Prepare

  1. Offline-First Architecture — Room as single source of truth, sync strategies, conflict resolution
  2. Pagination — Paging 3 library, RemoteMediator for network + DB, PagingData Flow
  3. Caching Strategies — Memory cache (LruCache), disk cache (Room), network cache (OkHttp), TTL
  4. Multi-Module Architecture — Feature modules, core modules, dependency rules, build speed
  5. Build Optimization — Gradle build cache, configuration avoidance, module boundaries
  6. Image Loading — Coil/Glide internals, memory management, disk caching
Tip

Framework for system design answers: 1) Clarify requirements, 2) Define the data model, 3) Design the architecture layers, 4) Discuss trade-offs, 5) Address edge cases (offline, errors, testing). Use this structure every time.

10 / Behavioral

Soft Skills Matter

Days 19–20 STAR Method Leadership

At Senior level, 30-40% of the evaluation is behavioral. They're assessing leadership, mentoring, decision-making, and communication.

Definition

STAR Method: Situation (context), Task (your responsibility), Action (what you did), Result (measurable outcome). Prepare 5-6 stories that cover different themes.

Top 5 Behavioral Questions

  1. "Tell me about a time you mentored a junior developer." — Show patience, structured approach, measurable growth
  2. "Describe a technical disagreement with a teammate." — Show data-driven resolution, no ego, compromise
  3. "What's a technical decision you made that you'd change now?" — Show self-awareness, learning, humility
  4. "How do you handle tight deadlines with technical debt?" — Show pragmatism, communication, trade-off thinking
  5. "Tell me about a time you improved a process or tool." — Show initiative, impact, follow-through

12 / Quick Reference

Top 50 Questions

Must-Know Quick Answers

Quick-fire questions with concise answers. ⭐ = most frequently asked.

Kotlin (1–15)

#QuestionKey Answer
⭐ 1val vs var?val = read-only reference (not immutable!). var = reassignable.
⭐ 2== vs === ?== is structural (equals()). === is referential (same object).
⭐ 3Data class: what's generated?equals, hashCode, toString, copy, componentN. Body properties EXCLUDED.
⭐ 4Sealed class vs enum?Sealed: subclasses can hold state, can be data/object. Enum: fixed set, no state per instance.
⭐ 5launch vs async?launch = fire-and-forget (Job). async = returns result (Deferred, call await()).
6Scope functions?let(it→result), run(this→result), with(this→result), apply(this→obj), also(it→obj).
7inline/reified?inline copies function body at call site. reified preserves generic type at runtime (requires inline).
⭐ 8Coroutine vs Thread?Coroutine: lightweight, suspendable, many per thread. Thread: OS-level, expensive (1MB stack).
9Flow vs LiveData?Flow: Kotlin, richer operators, cold. LiveData: Android, lifecycle-aware, limited.
⭐ 10StateFlow vs SharedFlow?StateFlow: has value, deduplicates, replay=1. SharedFlow: configurable replay, no initial value.
11Structured concurrency?Parent-child coroutine trees. Parent waits for children. Parent cancel = children cancel.
12Variance: in vs out?out = producer (covariant). in = consumer (contravariant). POCI mnemonic.
13Extension limitations?Resolved statically. Can't access private. Member always wins. No polymorphism.
14lateinit vs lazy?lateinit: var, non-null, mutable. lazy: val, computed on first access, thread-safe.
15Nothing type?Bottom type, subtype of everything. Functions that never return (throw). Works with ?: for smart types.

Android (16–35)

#QuestionKey Answer
⭐ 16Activity lifecycle on rotation?onPause → onStop → onDestroy → onCreate → onStart → onResume. ViewModel survives.
⭐ 17remember vs rememberSaveable?remember: survives recomposition. rememberSaveable: + config changes. Neither: process death.
⭐ 18collectAsStateWithLifecycle?Stops collection when lifecycle < STARTED (app backgrounded). Saves resources, prevents crashes.
⭐ 19MVVM layers?View → ViewModel → Repository → DataSource (API/DB). State down, events up.
20@Provides vs @Binds?@Provides: types you don't own. @Binds: interface→impl binding (more efficient).
⭐ 21LaunchedEffect vs rememberCoroutineScope?LaunchedEffect: composition lifecycle. rememberCoroutineScope: user events (clicks).
22Room Flow queries?Auto-emits new data when table changes. No manual refresh needed. Reactive.
23viewModelScope vs lifecycleScope?viewModelScope: ViewModel lifecycle. lifecycleScope: Activity/Fragment lifecycle.
24WorkManager vs Service?WorkManager: guaranteed, survives death, constraints. Service: long-running foreground work.
25Compose stability?@Stable/@Immutable: skip recomposition. Use immutable data. key in LazyColumn.
26ANR causes?Main thread blocked >5s (I/O, heavy computation). Fix: withContext(IO), WorkManager.
27Memory leaks?Inner class holding Activity ref, unregistered listeners, static context ref.
28Repository pattern benefit?Abstracts data sources. Single source of truth. Testable with fakes.
29Process death handling?SavedStateHandle in ViewModel. Small UI state only (IDs, scroll position).
30Navigation: popUpTo inclusive?Pops destinations up to target. inclusive=true also pops the target. Login→Home pattern.

System Design & Advanced (31–50)

#QuestionKey Answer
31Offline-first design?Room as source of truth. API syncs to DB. UI observes DB via Flow.
32Multi-module benefits?Build speed, code ownership, feature isolation, reusability.
33Paging 3 components?PagingSource (single source), RemoteMediator (network+DB), PagingData (Flow).
34ProGuard/R8?Code shrinking, obfuscation, optimization. Keep rules for reflection/serialization.
35Certificate pinning?Verify server's certificate matches expected. Prevents MITM. OkHttp CertificatePinner.
⭐ 36Design a chat app architecture?WebSocket for real-time, Room for local cache, Repository with offline queue, pagination.
37Image loading internals?Memory cache → Disk cache → Network. Downsampling. Lifecycle-aware loading.
38Gradle build cache?Caches task outputs. Configuration avoidance for faster config phase.
39Deep links?URI pattern matching in manifest/nav graph. Deferred deep links for install flow.
40App startup optimization?Lazy init, App Startup library, avoid heavy work in Application.onCreate().
41Compose vs XML migration?ComposeView in XML. AndroidView in Compose. Screen-by-screen migration.
42Hilt testing?@HiltAndroidTest, @UninstallModules to replace prod modules, @BindValue.
43Coroutine testing?runTest, UnconfinedTestDispatcher, Dispatchers.setMain/resetMain.
44Fakes vs Mocks preference?Fakes for repositories (reusable, catches contract bugs). Mocks for third-party.
45MVI when?Complex state interactions. Single state object. Time-travel debugging.
46Use Cases: always needed?No. Skip if pass-through. Use when business logic exists or shared across VMs.
47Compose Modifier order?Order matters! clickable before padding = different click area than after.
48derivedStateOf when?When computed value depends on state but is read more often than source changes.
49DataStore vs SharedPrefs?DataStore: async (Flow+suspend), type-safe, transactional. SharedPrefs: sync, ANR risk.
50Scoped storage?Android 10+. App-specific dirs without permission. MediaStore/SAF for shared files.
